# Custom Rules for Coding Style

- Write like a real beginner student, not AI-generated.
- Keep it simple and readable, no clever shortcuts or advanced tricks.
- Slightly imperfect in a natural way (like a student would write).
- Short simple variable names where it makes sense.
- Mix plain print() and formatted output naturally, not always the same style.
- Avoid words like: "robust", "leverage", "ensure", "streamline", "optimal".
- Minimal comments only where truly needed. Keep them short and plain. No comment on every single line.
- No emojis. No fancy markdown or overly professional headers. Plain section names. Do not add an explanation after every block of code.
- Use basic built-in logic, avoid complex one-liners. No heavy abstractions or unnecessary classes/functions.
- If using loops, sometimes use range(n) instead of always enumerate.
- Variable names must be different from reference project trekking-app-mad2.
- Route URLs and Python/JS function names must be completely different from the reference project to avoid plagiarism (e.g., use api/join-trekker instead of api/register, index_view instead of home, etc.).
- Avoid method chaining.
- Code must be 100% original, not copied or adapted from the internet.
- Explain the logic briefly in simple plain words (2-4 sentences max, no bullet points, no bold text).
